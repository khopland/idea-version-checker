Reports Maven dependencies and build plugins with a newer stable version available from the project's Maven repositories.

Update messages are warnings by default. Configure patch, minor, major, other version changes, and deprecated/relocated artifact severity under Settings → Tools → Version Checker. Explicitly deprecated dependencies/plugins and Maven relocation notices are errors by default, including when no version update is available.

Checks use IntelliJ IDEA's Maven settings and active profiles. Results are cached for ten minutes. Use Tools → Check Versions → Current File or Whole Project to refresh them.

The quick fix updates a literal version or an exact property reference declared in the same POM. Updating a shared property affects every declaration using it.

Version properties are also highlighted under <properties>, including child overrides used by dependencies or plugins declared in parent POMs. Checks use the child's effective property value. The property quick fix edits the child override when its consumers agree on an update; conflicting or unchanged consumers require review. Bulk previews list inherited property consumers under Needs review.

For inherited dependency versions, choose Override version locally to add or replace the child dependency's version, or Update parent version to change its controlling version/property in an imported, non-ignored parent POM. The parent action names the POM it edits and can follow multiple parent levels. Shared consumers inherit that update. Changes to POMs or configuration invalidate these fixes. Editing external parent declarations and composite expressions requires manual review.

When a dependency version comes from an exact property in the parent chain, Define <property> in this POM creates the matching property under the child's <properties>. The XML preview lists the affected artifacts; all used consumers must agree on the same update. Unused ordinary management entries are listed separately as unchecked metadata changes; BOM imports and plugin-management references still require agreed checks. The parent and its version references remain unchanged. Inherited dependencies are checked even without a child dependency declaration; unused parent management catalogs are omitted. Imported BOM properties, profile ambiguity, non-version uses, Maven config overrides and imported descendant subtrees require manual review. An existing local property keeps its normal update action. The action uses the IDE's undo command and stale-input guards. Reload Maven to check the resulting effective dependency versions; availability of a newer version does not establish a security fix or compatibility with the parent's tested dependency set. Parent upgrades and removal of redundant overrides remain manual decisions.

Build plugins in build/plugins and build/pluginManagement/plugins are supported. A <parent> version is updated in place when the parent is not a project in the workspace. Snapshots, version ranges, reporting plugins, build extensions and unmanaged transitive dependencies are outside this inspection's scope.
