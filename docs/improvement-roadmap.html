02 / Current delivery

Merged features and acceptance work.

1. Confirm inherited Maven versions

Capture expected versions from proven inherited-property consumers. Offer an explicit check of the imported Maven model after the requested full native import completes. Require identical physical inputs before and after that import and at verification; unrelated resolution events invalidate evidence.

Acceptance: pre-import is unknown; a matching fresh model confirms its effective version; a mismatch reports actual vs expected. This verifies imported version facts, not runtime behavior, vulnerability remediation or successful tests.

2. Show one update session

Attach declaration changes, provider reload outcomes, npm synchronization and supported version verification to the update that produced them. Keep a bounded project-lifetime history and explicit unknown states for unobserved outcomes.

Acceptance: retained actions cannot attach to a newer update; cancelled follow-ups preserve declaration facts; project disposal clears state; later input changes prevent stale verification. Native lockfile writes remain separate from declaration undo.

3. Keep incomplete checks visible

Project cached observation coverage into the tool window independently of display filters. Show checked, skipped, manual review, failed, pending and unknown counts, with source-specific next actions in details.

Acceptance: zero matching updates does not hide incomplete checks. Observation counts must not be mislabeled as unique physical declaration totals. Opening or filtering the view runs zero native queries.

4. Make acceptance repeatable

Record the exact archive hash, source, IDE build, runtime, fixture, cold/warm state and evidence for each scenario. Exercise keyboard navigation, narrow layout, scaling, themes, failures, cancellation and lifecycle.

Acceptance: test both IDEA 2026.1.4 and 2026.2.3. Mark unavailable cases blocked or not run. Never relabel historical ZIP evidence as current acceptance.

03 / Validation contract

Evidence belongs to a candidate.

  1. Automated prerequisites: default tests, native Maven/npm/Gradle integration, Maven 4 where supported, packaging, project configuration and both IDE verifier targets.
  2. Exact-ZIP native checks: isolated profiles and clean plugin extraction; inspect logs to confirm the loaded plugin. Run the repository’s docs/ide-acceptance.md matrix and retain sanitized evidence.
  3. Measurements: first visible result, review-ready time, filter/table response and typing during background work; measure atomic writes separately. Collect at least three cold/warm runs before setting budgets.
  4. Release gate: record passed, failed, blocked and not-run scenarios independently. Automated compatibility does not certify keyboard accessibility, resolved versions or working application builds.

Historical 1.3.0 evidence stays historical. Combined candidate validation: 721 default/native tests and six Maven 4 tests passed; both supported IDE verifier targets are compatible. Exact-ZIP native smoke on both IDEA versions confirmed inherited-property creation, separate import completion, explicit effective-version confirmation and undo invalidation. The broader accessibility/performance matrix remains uncompleted; see the acceptance record in #52 for archive identity, platform error caveats and evidence limits.

04 / Subsequent work

Expand after the journey is observable.

  • Preview expiry presentation: the immutable ready/checking/failed/applying/accepted/closed model now covers dialog intent, cancellation and late apply completion. Consider an explicit expired state only with an authoritative lease observation; keep provider guards decisive.
  • One ownership expansion: choose named local Gradle catalogs or broader inherited Maven bulk scope from observed friction. Require native owner/consumer fixtures before enabling new edits.
  • Lockfile diff integration: capture native pre/post snapshots before presenting an integrated diff; preserve partial-write and unknown-output semantics.
  • Cross-platform smoke: add bounded Windows/macOS native smoke once the repeatable acceptance fixture and evidence format are established.
  • Research: shortlist-only npm engine/peer metadata, release dates and missing-data behavior; versioned shared policy with explicit precedence and diagnostics.

Defer vulnerability enrichment, automatic family grouping, extra package managers, persistent cross-session history and broad cache consolidation until their separate evidence and semantics are defined.
