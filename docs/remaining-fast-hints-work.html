Second / Smaller interaction improvements

Make each decision quicker.

These are optional improvements from the review. They can be delivered separately from native resolution changes.

UX / Copy

Shorten routine hints.

Lead with the package, update type and version change. Put longer range, repository or manual-review explanations in secondary detail.

Done when: Routine hints are easier to scan and retain the information needed to choose an action. Review Maven, npm and Gradle together.

UX / Shared changes

Show the scope of Maven shared edits.

Maven parent/managed choices already identify their destination file; npm workspace actions already show declaration counts. Add consistent affected-consumer information for Maven shared/property/parent choices where it can be determined accurately.

Done when: The local versus shared choice explains its scope before selection, with accurate counts and existing ownership guards.

UX / Save behavior

Save only required build inputs.

Current-file refresh and preview actions still call saveAllDocuments(). Determine which build inputs native resolution needs and save those, or explain when broader saving is required.

Done when: Unrelated editing is preserved while required sibling POMs, build files and configuration still reach native resolution. Verify unsaved-input and stale-result handling.

UX / Noise control

Ignore a specific published version.

Add an optional action to dismiss one artifact/version update without suppressing unrelated updates. Define its scope, persistence and interaction with bulk review before implementing it.

Done when: The choice is reversible, survives for its intended scope, and leaves other artifacts and later releases visible.

Information-level patch severity is already configurable. A one-click low-noise preset could be considered later; it is not missing severity support. Repeated preview invocations already focus the existing dialog.

Third / Only when traces justify it

Evaluate changes to native resolution.

These remain experiments. Choose one when measured native setup or repeated goals dominate waiting, and compare both elapsed time and exact update results before keeping it.

G
Gradle / Deferred

Batch requests by linked build.

Explore one native invocation per linked root and update mode, preserving each source file and declaration’s owning resolution context. Avoid making the selected editor wait for all modules.

Keep it when: Representative multi-module builds show fewer invocations and less waiting, with equivalent results for catalogs, platforms/BOMs, attributes, substitutions, locks and cancellation.

M3
Maven / Deferred

Reduce repeated plugin branch queries.

Current patch/minor plugin checks can run a goal for each version branch. Test per-artifact rules or another compatible query approach that reduces those invocations.

Keep it when: Goal counts and elapsed time improve while patch/minor boundaries, ignored versions and Maven-version prerequisites produce equivalent candidates.

M4
Maven / Deferred

Reuse sessions across compatible modules.

Current Maven checks keep a fresh embedder per POM. Explore reuse only if embedder/session setup is a significant measured cost, with explicit compatibility and lifecycle boundaries.

Keep it when: Setup and elapsed time fall while repositories, authentication, profiles, configuration, refresh, cancellation and plugin unload remain correct.
